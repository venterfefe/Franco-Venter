Building a Self-Hosted AI Assistant: Nanobot

I built it. It works. I'm still not sure what to do with it.

April 13, 2026

I have long wanted to run my own AI assistant but lacked a compelling reason to do so — until I discovered nanobot, a lightweight self-hosted AI agent from the Data Intelligence Lab at HKU. It appeared credible on face value and inspired me to build it myself.

The Project: nanobot

Nanobot is approximately 4,000 lines of Python code initially inspired by OpenClaw. Key features include:

  • Connects to LLM backends (Claude/ChatGPT via OpenRouter)
  • Self-hosted server operation
  • Telegram/WhatsApp interface for phone accessibility
  • Persistent memory, web search, background agents, and scheduled cron jobs

The core concept: AI in your pocket running on personal infrastructure with embedded context.

The Build

To address privacy concerns about OpenClaw's data access, I deployed a Linux server via Hetzner (~$7/month, located in Norway). The setup involved:

  • Provisioning the Linux server
  • Cloning the nanobot repository with dependencies
  • Configuring the LLM gateway, API keys, and Telegram bot token
  • Running nanobot in a tmux session for persistence
  • Testing via Telegram messaging

Server Options

A VPS is essentially a rented Linux computer running 24/7 in the cloud. Hetzner was chosen for simplicity, with minimal monthly maintenance required.

Configure the Environment

Nanobot requires two primary inputs: an LLM gateway API and a Telegram bot token (easy setup via @BotFather).

I evaluated four LLM gateway options:

  • OpenRouter — easiest entry point, 300+ models, consolidated billing with ~5% markup for non-BYOK
  • LiteLLM — open source, self-hosted, customizable but requires engineering overhead
  • Vercel AI Gateway — Vercel ecosystem integration, limited otherwise
  • LLM Gateway — managed infrastructure, 300+ models, no markup with BYOK

I initially struggled with LLM Gateway configuration, reverting to OpenRouter (mentioned in nanobot's setup instructions) using BYOK with $5 credit activation. Brave Search integration was recommended for web capabilities, offering $5 monthly credits (~1,000 searches).

What It's Actually For

The potential use cases that stood out:

  • Daily briefings via cron — market digests (ASX performance, macro developments, RBA watch) delivered to Telegram at 7am
  • Context-aware advisory — persistent memory retains context across sessions without re-explanation
  • Background research — web search scoped to specific engagements; competitive intelligence and market data
  • Drafting and communications — first drafts, emails, client notes, outreach copy triggered via Telegram

Where I Got Stuck

Despite the promise, I identified real barriers to adoption:

  • I won't authorise automated financial transactions
  • It's redundant with existing tools (email drafting, task management, market news)
  • Native LLM research capabilities (Claude, ChatGPT) are already sufficient
  • My non-coder status eliminates code review needs

After installation, the weather forecast automation proved impractical ($0.11 API cost on Claude), though cheaper alternatives like GPT-4o mini exist.

Real Value Proposition

Despite the struggles, three genuine benefits emerged:

  • Persistent memory — unlike standard Claude, nanobot remembers context across sessions permanently
  • Always-on task capture — quick Telegram messaging for logging or Todoist integration without app-switching
  • Automation companion — natural language workflow triggers within existing automation stacks

Closing Thoughts

Building a self-hosted AI assistant accessible 24/7 from a phone with personal context integration proved genuinely interesting. But it also surfaced a broader AI adoption challenge: without a pre-identified painful problem, tools remain hobby projects rather than integrated solutions.
